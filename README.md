# 予備論文 添削ボード

予備試験・司法試験・旧司法試験の論文答案を、出題趣旨と合格答案の基準に照らして評価する1ページのサイトです。APIキーなしで動きます。

- **過去問の読み込み**：試験・年度・科目を選んで「読み込む」を押すと、法務省が公表している問題文と出題趣旨が入る。
  - 予備試験：平成23年〜令和7年
  - 司法試験：平成18年〜令和7年（選択科目も含む）
  - 旧司法試験：平成14年〜平成22年
- **自動評価（APIなし）**：出題趣旨の論点ごとにキーワードを用意してあり、答案がどの論点に触れているかを調べて、A圏〜D〜F圏の目安を出す。条文、分量、書き写し、完走も評価に入る。
  - 過去問以外の問題でも、「骨格メモ」に論点を1行ずつ書けば、その語句で評価する。
- **自動チェック**：字数、CBT換算のページ数、条文、数字つき事実の拾い率、問題文の書き写し、段落ごとの三段論法の目印。
- **自己チェック**：合格答案と比べる8項目。
- **合格答案ライブラリ**：過去問ごとに合格者の再現答案を評価つきで登録できる。登録した問題では、自動評価とAI添削が合格答案を基準にする。
- **AI添削（当てはめまで）**：論点ごとに規範・当てはめ・結論を◯△×で判定し、使えている事実と使っていない事実、答案への具体的な指摘、合格答案との差、当てはめの書き直し例を出す。使い方は3つ（下の「AI添削の使い方」）。
- **履歴**：ブラウザに保存。JSONで書き出し・読み込みができる。

## AI添削の使い方

| 使い方 | 費用 | 準備 |
|---|---|---|
| **claude.ai 版で開く**（おすすめ） | 自分のClaudeの利用枠を使う。API料金はかからない | なし。初回だけ「このページがClaudeを使う」許可を求められる |
| GitHub Pages 版でAPIキーを使う | 使った分だけAPI料金 | 「設定」でAPIキーを入れる（標準モデルは claude-opus-5-5） |
| 「プロンプトをコピー」してClaudeのチャットに貼る | 自分のClaudeの利用枠 | なし。結果は文章で返る（表にはならない） |

- claude.ai 版は、このリポジトリの `index.html` をアーティファクトとして公開したもの。合格答案ライブラリは claude.ai のあなた専用の保存領域に入り、ほかの人には見えない。
- claude.ai 版を更新するときは `python3 tools/build_artifact.py 出力先.html` で変換し、データJSON 4つと一緒に同じアーティファクトへ公開し直す。

## 合格答案ライブラリ

- 「合格答案」タブで、いま読み込んでいる過去問に答案を登録する。評価（A〜F、評価不明なら「合格者」）と出典も残す。
- まとめて入れるときは、同じ形式のJSON（`[{"id", "key": "yobi/R6/刑訴", "rank": "A", "src", "text"}, …]`）を「読み込む」で選ぶ。
- 評価A・B・「合格者」の答案が基準になる。自動評価は、それらの半数以上が触れている論点だけで帯を判定し、合格答案もあまり触れていない論点は「加点」と表示して減点に使わない。分量と数字つき事実の拾い率も合格答案の中央値と並べる。
- AI添削には、基準の答案を2通まで、低評価の答案を1通まで渡して比べさせる。
- 予備校の解説レジュメなどは、評価で「解説・骨格（答案ではない）」を選んで登録する。AI添削が論点・要件・使う事実と推認の筋道の目安として参照する。自動評価の基準には入れない。
- 再現答案集などから写した答案や予備校の教材は、自分の学習用にとどめて公開しない（このリポジトリにも入れない）。

## 自分用の問題データ

- 法務省のサイトにない年度（旧司法試験の平成13年以前など）は、問題データのJSONを「合格答案」タブの「読み込む」で入れられる。入れた年度は「添削」タブの年度の一覧に「自分用データ」として出る。
- 保存先は合格答案ライブラリと同じ（claude.ai ではその人専用の保存領域、それ以外はブラウザ）。ほかの人には見えない。このリポジトリにも入れない。
- 形：`{"kind": "problems", "exam": "kyushi", "years": {"H13": {"yearLabel": "平成13年", "sources": [{"title", "url"}], "items": [{"id": "憲法1", "title": "憲法 第1問", "subject": "憲法", "problem": "…", "skel": {"note": "…", "pillars": [{"label", "any": […], "w", "core"}], "articles": [{"label", "any": […]}]}}]}}}`
- 法務省の出題趣旨がないので、論点キーワード（skel）は出題趣旨によらず作ったものになる。

## 自動評価の見方と限界

- 答案に論点の語句が**あるかどうか**を見ている。論じ方が正しいか、当てはめが上手いかは判定しない。
- 論点ごとに3段階で判定する。
  - **◯**：問題文にない語（判例名・規範・要件の言葉など）で触れている。または、問題文にある語を「といえる」「当たる」などの評価の言葉と同じ文で使っている。
  - **△**（半分に数える）：問題文にある語を出しただけ。事実を写しただけでは論点を論じたことにならないため。
  - **×**：触れていない。
- 総合点は、論点カバーと分量（その問題・科目の合格答案〔A・B〕の字数の中央値に対する比）を合わせて出す。重みと帯の境目は、評価つきの再現答案391通（予備試験 H26〜R7）に合わせて決めた。
  - 論点の語は低評価の答案もほぼ書いているので、論点カバーだけでは差がつかない（F評価の答案でもカバーは平均7割）。分量を合わせると、実際の評価との一致が上がる。
  - 391通での一致：「A圏」と出た答案の4分の3が実際にA・B評価、「D〜F圏」と出た答案の半分あまりが実際にD〜F評価。B圏とC圏の区別はあまり当たらない。同じ問題のA・B答案とD〜F答案を正しく並べる割合は77%。
  - 司法試験・旧司法試験は評価つき答案での調整をしていない。分量の目安だけ、司法試験5,200字・旧司法試験1,600字に置き換えている。
- 次の場合は、点が高くても評価の帯を下げる。
  - 枠組みの論点が×ならC圏まで、△ならB圏まで。
  - 「設問2」などの論点に一つも触れていない（設問が丸ごと空）ならC圏まで。
- 答案に「設問1」「設問(2)」「〔設問2〕」のような見出しがあれば、「設問2：…」の論点は設問2の部分だけで判定する（別の設問に書いた語では◯にならない）。「第1」「第2」だけの見出しは、番号が設問と同じ組のときだけ設問の区切りとみる（「第1 甲の罪責」のような答案があるため）。
  - 論点の語は並んでいるのに、事実を評価する文がほとんどない（論点の羅列）ならB圏まで。
  - 問題文の書き写しが25%超、条文番号なし、のそれぞれで1段下げる。
- 「取り消し／取消し」「差し押さえ／差押え」「第二十一条／21条」のような表記ゆれは同じ語として扱う。
- 別の言い方で書いた論点は「×」になることがある。×の行に「探した語」が出るので、自分の答案と見比べる。
- 論点キーワードには2種類ある。
  - **精選**：出題趣旨を読んで論点ごとに作ったもの。
  - **自動抽出**：出題趣旨から条文・判例名・用語辞書で機械的に抜いたもの。精度は低め。
  - どちらを使ったかは、評価欄の下に表示される。
- 点は目安で、実際の採点とは異なる。最終的な評価はAI添削か、自分で出題趣旨を読んで確かめる。

## 自動評価の確かめ方（開発用）

`tools/bench.mjs` は、`index.html` の自動評価をそのまま呼んで、次を確かめる。Node.js と playwright（Chromium）が要る。

```
node tools/bench.mjs yobi            # 予備試験。shiho・kyushi も指定できる
node tools/bench.mjs yobi --detail   # 問題ごとの内訳も出す
```

- **問題文をそのまま答案にしたとき**：低く出るべき（書き写しで点が出ないか）。
- **出題趣旨を答案にしたとき**：論点カバーが高く出るべき（キーワードが的外れでないか）。
- **論点名だけを並べたとき**：A圏にならないこと。
- **答案サンプル**（`tools/fixtures/`）：手書きの答案が期待どおりの帯に入るか。期待と違えば終了コード1で終わる。キーワードや判定を変えたら、これが全部OKのままか確かめる。
- **評価つきの再現答案**（任意）：合格答案ライブラリから書き出したJSONを `--real` で渡すと、実際の評価との順位相関と、帯ごとの当たり方を出す。再現答案は他人の文章なので、このリポジトリには入れない。

```
node tools/bench.mjs yobi --real 合格答案.json
```

## デスクトップに置いて使う（1ファイル版）

過去問データを中に入れた HTML を1つ作り、デスクトップに置いてダブルクリックで開く。インターネットにつながっていなくても、過去問の読み込み・自動評価・合格答案との比較が使える（AIの添削は「設定」のAPIキーか「プロンプトをコピー」を使う）。

```
python3 tools/build_desktop.py 予備試験添削.html [--extra 自分用の問題データ.json] [--pass 合格答案.json ...]
```

`--extra` の問題データは年度の一覧に「自分用データ」として、`--pass` の答案は「同梱」として出る（同梱分はページからは消せない）。書いた答案やあとから登録した答案はそのパソコンのブラウザに保存される。自分用のデータを入れたファイルは公開しないこと。

## GitHub Pages で公開する手順（10分）

1. **リポジトリを作る**
   - GitHub にログインして、右上の「＋」→「New repository」を押す。
   - Repository name に `yobi-tensaku` と入れる。
   - 「Public」を選ぶ（無料プランで Pages を使うには Public が必要）。
   - 「Create repository」を押す。
2. **ファイルを上げる**
   - できたページの「uploading an existing file」を押す。
   - zip を展開した中の6ファイル（`index.html`・`README.md`・`exams-index.json`・`yobi-data.json`・`shiho-data.json`・`kyushi-data.json`）をまとめてドラッグして入れる。**.json の4つも必ず入れる**（問題文のデータ）。フォルダはない。
   - `H18.json`・`R7 (20).json` のような年度別のファイルは要らない（中身は `*-data.json` に全部入っている）。上げてしまったら消してよい。
   - 下の「Commit changes」を押す。
3. **Pages を有効にする**
   - リポジトリの「Settings」→ 左の「Pages」を開く。
   - 「Branch」で `main` と `/ (root)` を選んで「Save」を押す。
   - 1〜2分待つと、上に `https://（あなたのユーザー名）.github.io/yobi-tensaku/` が出る。そこを開けば使える。

更新するときは、新しいファイルを同じ手順で上げ直す（同じ名前なら上書きされる）。

**注意**：`index.html` をパソコンでダブルクリックして開くと、ブラウザの制限で過去問データを読めない（ほかの機能は使える）。GitHub Pages の URL で開く。

## プライバシー

- 答案・履歴・APIキーは、**開いているブラウザの中（localStorage）にだけ**保存される。GitHub には送られない。
- リポジトリは Public なので、**ページのコードとデータは誰でも見られる**。答案は見られない。
- **AI添削（API）を使ったときだけ**、入力した答案と問題文が Anthropic に送られる。
- 共用のPCでは APIキーを保存しない。「設定」→「キーを削除」で消せる。

## 出典

- 問題文・出題趣旨：法務省ウェブサイト（https://www.moj.go.jp/jinji/shihoushiken/shikaku_saiyo_index.html ）。法務省ウェブサイトのコンテンツは「公共データ利用規約（PDL1.0）」に基づいて利用できる。
- 本サイトでは、PDFから文字を取り出し、科目ごとに分け、改行を整えて掲載している（編集・加工あり）。取り出しの際に図表・レイアウトが崩れている箇所があるので、正確な文面は各問題の「出典」リンクから原本のPDFで確かめる。
- 論点キーワード・評価のしくみは本サイトが作成したもので、法務省が作成したものではない。
